## 1. 背景与版本目标

星野社区是面向 18–30 岁用户的兴趣社区产品，覆盖 Android 与 iOS 双端，当前线上稳定版本为 3.1.9（2026-06-11 全量发布）。3.2.0 的核心版本目标是：**提升新用户首日激活与内容消费**。对应两条验收线：

1. 新用户次日留存（next_day_retention）不低于 3.1.9 同期水平（约 0.31，Android 与 iOS 分平台考核）；
2. 新用户首日内容消费率（首日完成 ≥3 次内容详情浏览的占比）提升 3 个百分点。

## 2. 需求清单

| 编号 | 需求 | 说明 | 影响链路 |
| --- | --- | --- | --- |
| R1 | 启动链路优化 | 首屏加载由串行改为并行：先渲染骨架屏，再回填登录态与推荐流 | 冷启动耗时 |
| R2 | 登录 SDK 升级 | 登录 SDK 由 4.9.2 升级至 5.4.0，支持运营商预取号与一键登录 | 登录成功率、启动耗时 |
| R3 | 新手引导改版 | 引导流程由 5 步精简为 3 步，兴趣选择前置 | 首日激活 |
| R4 | 推荐冷启动 | 无行为新用户首刷使用热门 + 地域兜底内容池 | 首日消费 |

说明：R1、R2 由客户端研发中心排期，R3、R4 由产品与算法团队共同推进。R3 不随包体开关控制，通过实验平台灰度，其观测窗口与 3.2.0 发布窗口存在重叠（详见 product_kb 中的产品评审会议纪要）。

## 3. 发布与灰度计划

- 构建号 3200 / 3201，计划 **2026-08-20 09:00 Android 全渠道全量发布**，iOS 同日提审；
- 不做客户端灰度，原因是登录 SDK 5.4.0 与首屏改造存在耦合，灰度会造成线上并存两套启动链路，埋点口径无法对齐。

## 4. 风险与依赖

- 登录 SDK 5.4.0 为厂商主版本升级，初始化方式不兼容 4.x，需完成接入回归后方可封版；
- 首屏并行化后，低端机（RAM ≤ 4GB）出现初始化资源竞争的概率上升，需研发侧同步给出监控方案；
- 埋点字典已更新至 1.4.0（新增 device_tier、launch_type 字段），数据侧需在发布前完成口径校验。

## 5. 验收与观测

发布后 D+1 起，由数据运营部输出次日留存、崩溃率、DAU 日报，观测窗口为 2026-08-20 至 2026-09-02。若新用户次日留存低于 3.1.9 同期 1 个百分点以上，触发回滚评估流程。

## 6. 变更记录

- 2026-08-08 v3.2.0 定稿，补充低端机监控要求与发布后观测方案。
