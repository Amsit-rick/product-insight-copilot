# 3.2.0 次日留存波动故障复盘（内部）

| 项目 | 内容 |
| --- | --- |
| 归属知识库 | engineering_kb |
| 文档版本 | 1.0.0 |
| **密级** | **confidential（内部限阅）** |
| 复盘范围 | 2026-08-20 09:00 ~ 2026-08-26 24:00 |
| 参与部门 | 研发中心、质量保障部、数据产品部 |
| 更新日期 | 2026-08-31 |

## 1. 现象

数据侧反馈：Android 3.2.0 发布后新用户次日留存由约 0.31 降至约 0.26，其中低端机与 channel_a 分群降幅最大；iOS 未见变化。

## 2. 监控数据（本复盘采用的看板口径）

| 指标 | 3.1.9 基线（08-01 ~ 08-19） | 3.2.0（08-20 ~ 08-26） | 判定 |
| --- | --- | --- | --- |
| Java 层崩溃率（研发崩溃看板） | 0.51% | 0.53% | 无明显上升 |
| 服务端登录成功率 | 98.8% | 98.7% | 正常 |
| 首屏可交互耗时 P50（Android 全量） | 1.9s | 1.6s | 改善 |
| 首屏可交互耗时 P50（低端机） | 3.2s | 3.4s | 轻微劣化，未超阈值 |

## 3. 结论

**监控期间未发现崩溃率上升，登录成功率正常。** 启动链路改造（ENG-2、ENG-3）在整体口径上带来首屏耗时改善，不构成留存下滑的解释；低端机 P50 劣化 0.2s 未超过 5% 告警阈值，判为可接受波动。留存下滑的原因未定位。

## 4. 已执行的验证动作

- 08-23 18:00 通过实验平台对 30% 用户关闭启动预热（`enableStartupPrewarm=false`），对比 08-24 ~ 08-26 次日留存：关闭组 0.259、开启组 0.262，差异处于噪声范围，**未能复现留存回升**；
- 检查推荐与内容池配置，未发现 3.2.0 侧策略变更；
- 检查登录失败码分布，服务端返回 4xx / 5xx 未见突增。

## 5. 遗留冲突与口径差异（未闭环）

1. 客服工单与商店评论显示「启动闪退」「登录失败」在 08-21 后集中出现，与本复盘结论**不一致**，构成冲突证据，需在最终报告中并列展示而非强行合并；
2. 复盘看板的崩溃率只统计 Java / Kotlin 层未捕获异常，**不含冷启动阶段的 native 崩溃**；而埋点口径的 crash_rate 包含 native 崩溃，两者不可直接比较；
3. 启动阶段进程崩溃的用户不会发出 `app_launch` / `user_login` 上报，服务端登录成功率的分母天然缺少这部分用户，因此"登录成功率正常"可能存在幸存者偏差；
4. 跟踪单 XC-2041 记录的 3 例低端机启动阶段 native abort 尚未闭环，需在 09-01 前补充 native 崩溃采集与按 device_tier 拆分的崩溃看板后重新判定。

## 6. 待办

1. 质量保障部：09-01 前完成 native 崩溃采集开关下发与验证；
2. 数据产品部：对齐崩溃率两种口径，输出差异说明文档；
3. 产品部：与客服中心对齐工单分类口径，形成单一事实来源。
