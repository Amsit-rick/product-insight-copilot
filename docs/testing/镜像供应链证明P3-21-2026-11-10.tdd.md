# 镜像供应链证明与 SBOM P3-21（2026-11-10）

## 1. 目标与边界

本轮为应用镜像增加与 Git 提交绑定的 BuildKit SLSA provenance 和 SPDX SBOM，验证 OCI index、应用 manifest、attestation manifest、镜像运行用户、VCS revision、构建参数、依赖解析和 SBOM 包清单，并把同一门禁加入远程 CI 配置与交付证据包。

真实演练仍使用 Windows 主机上的明文无认证回环 Registry，构建和验证属于同一 Docker daemon。它只能证明本地镜像证明材料可生成、可读取、可失败关闭地校验，不能代表镜像签名、企业 Registry、跨主机目标节点或生产发布审批已经完成。全部证据继续标记 `production_ready=false`。

## 2. 完成的工程改造

### 2.1 镜像证明与 SBOM 验证器

- Buildx 构建启用 `--provenance=mode=max` 和 `--sbom=true`；
- 校验 OCI index digest、唯一 `linux/amd64` 应用 manifest 及其唯一 attestation manifest；
- 校验 OCI revision、非 root 用户、`APP_RELEASE_SHA`、VCS revision/source 和 resolved dependencies；
- 校验 `runDetails.metadata` 的构建起止时间与非空调用标识，但不把调用标识写入证据；
- 校验 SPDX 2.3 和最小包数量；
- builder ID 或冗余 metadata VCS 字段由 BuildKit driver 决定，缺失时明确记录可用性，存在时必须通过一致性校验；
- 证据固定声明未验证签名、企业 Registry、跨主机和生产就绪。

### 2.2 自动化与交付证据契约

- 新增可重复执行的 PowerShell 演练脚本，拒绝脏工作区，避免 provenance SHA 与实际构建内容不一致；
- GitHub Actions 增加隔离回环 Registry、带证明材料的镜像构建、验证和提交绑定制品上传；
- release evidence bundle 的强制附件由三类增至四类，供应链证据缺失或 SHA 不一致时失败关闭；
- 当前 Git 远端只有 Gitee，尚未发生一次真实 GitHub Actions 运行，因此 CI 配置存在不等于远程 CI 已验证。

## 3. 真实运行中发现并修复的问题

### 3.1 空 builder ID

Docker Desktop 的 BuildKit Docker driver 会生成 `builder: {"id": ""}`。这不是 provenance 缺失。验证器改为要求 builder 对象存在，非空 ID 只输出指纹；空 ID 明确记录 `builder_identity_available=false`，同时继续强制校验 Git SHA、VCS source、构建时间和调用标识。

### 3.2 metadata VCS 字段并非稳定输出

同一 driver 的不同构建中，`runDetails.metadata.vcs` 可能存在也可能省略，而 `externalParameters.request.root.request.args` 中的 `vcs:revision` 和 `vcs:source` 稳定存在。最终规则将根请求 VCS 作为硬门禁；冗余 metadata VCS 若存在则必须一致，若省略则记录 `metadata_vcs_available=false`。没有删除 OCI revision、构建参数或根 VCS 的 SHA 绑定。
