## 1. RED：修复前稳定复现

1. 已签收订单 + 客户称未发货，规则仍返回 `reship`。
2. 规则明确返回 `missing_information=[]` 时，被模型生成的缺失项覆盖。
3. 已有金额、物流和政策引用时，模型警告仍声称“无支付事实”“证据覆盖为 0”。
4. mock 报告可得到误导性的发布候选状态；非 mock 的候选正向路径不可达。
5. “启动分析”弹窗要求填写不会发送给后端的理由；原 E2E 也依赖该无效输入框。
6. 完整评测首次运行：前 8 条旧标签仍期望已签收订单直接补发，结果 `0/8`；修正标签后全量首次为 `225/228`，剩余 3 条“漏发商品”被错误分类成整单未发货。
7. 系统 Python 直接运行评测报 `ModuleNotFoundError: httpx`，证明当前项目虚拟环境仍依赖跨项目 `.pth`，不能宣称干净环境可复现。

## 2. GREEN：实现与回归

- 履约冲突同时识别中文状态、英文规范状态、最新物流和签收时间；明确未发货状态不会被 `shipped` 子串误判。
- 冲突动作固定为 `ask_customer`，风险固定进入 L3 主管复核，禁止直接退款或补发。
- `missing_information` 按“字段是否存在”裁决；空列表和 `None` 都不会回退到模型臆测。
- 模型警告按政策、支付、物流、轨迹时间和当前受控动作逐项核销；技术性模型分歧改为业务可读提示。
- “漏发了一个商品”归入 `missing_item`，“整单未发货”保留为 `not_shipped`；界面将后者显示为“未发货”。
- 评测集升级为 `tickets-1.1.1`，生成器与 JSON 同步，错误标签不再覆盖业务真值。
- 门禁拆分为 `local_demo_ready`、`candidate_ready`、`production_ready`；mock 只能通过本地演示门禁，真实适配器正向候选路径已有测试。
- 分析动作不再显示或校验理由输入框；E2E 明确断言弹窗中不存在 textarea。
- CI 实际接入 `verify_tickets.py` 和 `verify_ticket_l2_send.py`，不再只在注释中宣称覆盖。

## 5. 2026-09-30 基础设施与可用性整改复验

### RED：先在独立环境复现

- 全新 Python 3.12 venv（无跨项目 `.pth`）首次运行全量测试发现 15 项失败：`qdrant_client` 与 `langgraph.checkpoint.sqlite` 未在 `requirements.txt` 声明，Office 回退测试错误依赖“环境未安装正式解析器”。
- 新增健康探针与安全头契约测试，修复前 `/health/live`、`/health/ready` 均为 404，成功/错误响应均缺少安全头。
- 前端原本无 lockfile，`npm audit` 无法形成可复现审计；锁定后首次审计发现 2 个高危依赖告警。

### GREEN：实现与证据

- `backend/requirements.txt` 补齐 `qdrant-client`、`langgraph-checkpoint-sqlite`；Office 后备测试改为当前用例显式阻断优先解析器，不再假定机器环境。
- 新增 `/health/live`（只证明进程存活）与 `/health/ready`（数据库、缓存、执行后端/共享 checkpointer 结构化检查）；生产 readiness 在关键依赖失败时返回 503。
- 全局响应头统一加入 CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy；生产额外加入 HSTS。
- Dockerfile 改为仓库根上下文多阶段构建：`npm ci` 构建前端，复制 `frontend/dist` 到最终 Python 镜像；Docker HEALTHCHECK 改用 `/health/ready`。Compose API/worker 均切换到根上下文。
- GitHub Actions 与本地 CI 统一 `npm ci`、lockfile cache，并运行 58+15 live API 与售后角色 E2E；CI 启动等待改用 `/health/ready`。
- `scripts\\ci.ps1` 支持 `-PythonPath` 指定隔离解释器，便于持续审计依赖污染。
- 工单缺订单号时新增原工单补录接口 `PATCH /tickets/{id}/order`，前端在分析前提供“补录并分析 / 向客户索取 / 转人工”三项明确下一步，并记录审计。
- 修复全新 PostgreSQL 执行 004 时重复添加 `amount_source` 的真实迁移失败；新增一次性 PostgreSQL 快照恢复演练脚本。
