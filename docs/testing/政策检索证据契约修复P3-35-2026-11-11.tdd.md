# 政策检索证据契约修复 P3-35（2026-11-11）

## 1. 目标与边界

政策检索基准生成器已输出 `embedding_mode`、`embedding_model`、`embedding_stats`、
`strict_evidence_ok`、`independent_holdout` 和 `production_ready`，但发布报告验证器仍读取旧字段
`embedding=stub`。因此真实执行即使得到 Recall@5=100%、MRR=0.9375，也会被错误标记为
`not_verified`。

本阶段只修复本地零成本政策检索证据的契约漂移。它不把 stub embedding、8 条合成查询或
本地发布报告解释为真实模型质量、独立 holdout 或生产可发布证据。

## 2. 用户旅程与验收保证

- 作为发布负责人，我希望发布报告读取基准生成器当前真实输出，避免有效本地门禁被假失败阻断。
- 作为审计人员，我希望报告自行重算 Recall/MRR，并拒绝缺字段、回退、失败或越界生产声明，避免只相信摘要字段。
- 作为维护人员，我希望报告同时输出 embedding 模式和模型名，便于定位证据来自 stub 还是真实配置。


```text

```

RED 提交：`000a0a6 test(delivery): reproduce policy benchmark contract drift`。

## 4. GREEN 实现

发布报告验证器改为校验当前 v1 stub 证据契约：

- `embedding_mode == "stub"`；
- `embedding_model` 必须以 `stub-` 开头；
- `independent_holdout == false`，`production_ready == false`；
- `strict_evidence_ok == true`；
- `embedding_stats.failures` 和 `embedding_stats.fallbacks` 必须显式存在、为非负整数且等于 0；
- 保留原有的新鲜度、schema、top_k、样本量、逐用例结构、摘要重算、阈值和 `passed` 检查。

报告输出新增 `embedding_mode` 和 `embedding_model`，让消费者能区分证据性质。

GREEN 提交：`a1ad90b fix(delivery): validate current policy benchmark contract`。
