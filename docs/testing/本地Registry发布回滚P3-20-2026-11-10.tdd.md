# 本地 Registry 发布与镜像回滚 P3-20（2026-11-10）

## 1. 目标与边界

本轮验证不可变应用镜像能否发布到受控的本地 OCI Registry、从 Registry 获取远端 digest、删除本地 Registry 引用后按 digest 强制拉取，并依次完成当前版本上线和上一版本回滚。

本轮 Registry 仅绑定 Windows 主机回环地址，使用明文 HTTP、无认证，并且发布端和运行端属于同一个 Docker daemon。因此它只能证明本地发布与应用镜像回滚流程，不代表企业制品仓库、跨主机目标节点、镜像签名、数据库迁移回滚或生产发布批准已经完成。全部证据继续标记 `production_ready=false`。

## 2. 完成的工程改造

### 2.1 本地 Registry 与制品验证

- 新增只绑定 `127.0.0.1` 的独立 Registry Compose，镜像按 digest 固定并配置 CPU、内存和 PID 上限；
- 新增 Registry 制品验证器，校验源镜像 OCI revision，执行 tag、push，并通过 Registry API 获取 `Docker-Content-Digest`；
- 删除本地 Registry tag/digest 引用后按远端 digest 拉取，再校验 revision、RepoDigest 和非 root 用户；
- 明文 Registry 只允许显式授权的 localhost 或回环 IP，远程 Registry 默认要求 HTTPS；
- 证据固定声明 `enterprise_registry_verified=false`、`cross_host_verified=false` 和 `production_ready=false`。

### 2.2 上线与回滚演练

- 新增可重复运行的 PowerShell 演练脚本，拒绝覆盖同名现有 Compose 项目；
- 当前镜像和上一镜像均先发布、按 digest 拉取，再使用 release Compose 启动；
- 启动后同时等待 API readiness 和两个 Worker 的 Docker health 进入 `healthy`，避免在 Worker 启动窗口内误判失败；
- 当前版本和回滚版本均执行部署加固探针与四单队列探针；
- 演练结束自动移除临时容器、网络和卷，并恢复进程级环境变量。

### 2.3 运行中发现并修复的问题

首轮演练在 API 就绪后立即执行部署探针，两个 Worker 当时仍处于 `health: starting`，导致 `workers_healthy=false`。该失败是真实启动时序问题，不是业务回归。修复为按 Compose project/service 标签定位 Worker，要求至少两个容器并等待两者都进入 `healthy`，最长 90 秒；修复后完整上线与回滚演练通过。
