# 发布报告分支覆盖率门禁 P3-37（2026-11-11）

## 1. 目标与用户旅程

本任务由 P3-36 的真实覆盖率结果继续推导，没有独立计划文件。

- 作为发布负责人，我希望语句和分支覆盖率分别达到明确阈值，避免较高语句覆盖掩盖未测试的失败关闭分支。
- 作为维护人员，我希望本地与远程 CI 使用同一结构化校验器，避免两套门禁口径漂移。
- 作为审计人员，我希望覆盖率证据不越权声明全仓质量、Agent 准确率或生产就绪。

## 2. RED 证据

第一轮先要求本地 CI 和 GitHub Actions 启用分支统计，并增加发布报告边界测试：

- 结果：**1 failed / 45 passed**；
- 失败原因：两套 CI 都缺少 `--branch`；
- 检查点：`e2159d4 test(delivery): require release report branch coverage`。

随后识别到 `coverage report --fail-under=80` 校验的是综合比例，不等于分支本身达到 80%，因此增加结构化门禁契约：

- 结果：**4 failed / 45 passed**；
- 失败原因：独立校验脚本尚不存在，CI 也未生成和消费 coverage JSON；
- 检查点：`a2e4767 test(delivery): require separate branch coverage threshold`。

## 3. GREEN 实现

- 新增 `backend/scripts/verify_coverage_report.py`；
- 只接受启用了 `branch_coverage` 的 coverage.py JSON；
- 目标文件必须唯一匹配，语句/分支计数必须是合法非负整数，分母必须大于 0；
- 分别计算 `statement_percent` 和 `branch_percent`，任一低于阈值返回退出码 1；证据结构无效返回退出码 2；
- 本地 PowerShell CI 与 GitHub Actions 均执行 `coverage run --branch`、`coverage json` 和相同的 80%/80% 校验命令。

GREEN 检查点：`024eaf1 feat(delivery): enforce statement and branch coverage`。

## 5. 覆盖率与负向验证

结构化结果：

- 语句：**471/535 = 88.04%**；
- 分支：**107/132 = 81.06%**；

- 阈值：语句 80%、分支 80%，两项均通过。

将分支阈值临时提高到 90% 后，校验器输出 `branches=false` 并返回退出码 **1**，证明门禁不是只生成报告而不阻断。
