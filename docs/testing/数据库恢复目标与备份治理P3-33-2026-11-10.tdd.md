# 数据库恢复目标与备份治理 P3-33（2026-11-10）

## 1. 目标与边界

P3-32 已证明本地一次性 PostgreSQL 能从发布前快照恢复迁移历史、业务数据和 schema，但证据没有记录快照哈希、快照大小、恢复时间线和实测 RPO/RTO，也未进入统一目标节点准入。

P3-33 增加恢复目标测量和失败关闭门禁。它只判断本地演练证据是否完整、是否满足给定恢复目标，并单独暴露企业备份治理状态。加密、企业密钥、异地副本、保留策略和恢复访问审计缺少任一项时，不得声明企业备份治理通过。

本阶段没有修改正式数据库迁移，没有生成 DOWN SQL，也没有把测试 fixture 当作生产数据。

## 2. 用户旅程与验收保证

- 作为发布负责人，我希望发布准入读取同一候选版本的恢复目标证据，避免只验证应用镜像而忽略数据库恢复能力。
- 作为运维负责人，我希望知道快照是否完整、恢复时间线是否可信、实测 RPO/RTO 是否满足目标。
- 作为审计人员，我希望本地恢复通过与企业备份治理严格分开，避免单机演练冒充加密、异地和保留策略验收。

## 4. 工程改造

### 4.1 恢复目标验证器

新增 `backend/scripts/verify_database_recovery_objectives.py`，输出 `database-recovery-objectives-verification-v1`，校验：

- 原始证据 schema、大小、时效和执行状态；
- current / rollback 完整 Git SHA；
- `postgres_custom` 快照 SHA-256 和非零大小；
- 快照开始、完成、模拟故障、恢复开始、恢复完成的时间顺序；
- 时间戳计算值与证据中的 RPO/RTO 测量一致；
- 迁移历史、业务数据和候选 schema 均按预期恢复；
- 实测 RPO/RTO 不超过调用方给定目标；
- 输入不能自称 `production_ready=true`。

本地恢复目标通过时输出 `local_recovery_objectives_verified=true`。企业治理只有以下五项全部为真时才通过：

- `backup_encrypted`；
- `key_management_verified`；
- `offsite_copy_verified`；
- `retention_policy_enforced`；
- `restore_access_audited`。

### 4.2 PostgreSQL 演练证据增强

`scripts/rehearse-database-migration-rollback.ps1` 新增：

- 容器内计算快照 SHA-256；
- 快照字节数非零校验；
- 五个 UTC 时间点；
- `observed_rpo_seconds` 和 `observed_rto_seconds`；
- `backup_storage_scope=container_local_ephemeral`；
- 五项企业治理字段固定为 `false`。

固定为 `false` 是事实声明：当前脚本使用容器本地临时快照，没有企业 KMS、异地副本、正式保留策略或独立访问审计。

### 4.3 统一准入

`verify_target_release_admission.py` 将 `database_recovery` 增加为第八类必需证据，并新增：

- `database_recovery_objectives_verified`；
- `enterprise_backup_governance_verified`。

恢复证据的 `current_source_git_sha` 必须与候选 SHA 一致，并纳入 `admission_bundle_id` 的证据哈希集合。即使其他企业证据全部通过，企业备份治理为假时，机器准入仍然失败；工具仍不会授予最终发布权。

## 5. 失败关闭验证

| 场景 | 结果 |
|---|---|
| 快照哈希非法或大小无效 | `snapshot_integrity_verified=false` |
| 恢复完成时间早于恢复开始 | `recovery_timeline_verified=false` |
| 实测 RPO 超过目标 | `rpo_objective_met=false` |
| 实测 RTO 超过目标 | `rto_objective_met=false` |
| current SHA 不匹配 | `release_sha_verified=false` |
| 证据超过 24 小时 | `evidence_fresh=false` |
| 输入自称生产就绪 | `self_claims_safe=false` |
| 五项企业控制缺少任一项 | 本地恢复仍可通过，但 `enterprise_backup_governance_verified=false` |
| 统一准入缺少本地恢复目标通过 | `database_recovery_objectives_verified=false` |

历史 P3-32 真实证据没有新增字段。P3-33 验证器对该文件真实返回退出码 1，并阻断快照完整性、时间线、RPO/RTO 测量和目标检查，没有默认兼容放行。
