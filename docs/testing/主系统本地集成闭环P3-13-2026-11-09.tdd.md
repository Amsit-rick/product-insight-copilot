# 主系统本地集成闭环 P3-13（2026-11-09）

## 目标

把已完成的本地 Sandbox 从“接口单独可用”推进到“主系统真实调用”，并验证反思、独立 worker、同机跨进程恢复、真实模型售后闭环和当前检索基线。所有业务事实与指标均为合成数据，写入隔离库，不把本轮结果冒充生产证据。

## 实现

- `backend/scripts/local_integration.py`：可重复启动主 API、Sandbox 和独立 worker；使用独立数据库、对象目录、缓存与 SQLite checkpointer，保留 `.env` 中的模型配置。
- `backend/scripts/verify_local_integration_workflow.py`：验证主系统 HTTP 事实接入、失败场景、真实模型 Agent、反思、主管审批和指标同步；不发送回复、不执行退款。
- `backend/scripts/verify_local_integration_recovery.py`：在两个实际 Python 进程间验证队列和人工中断检查点恢复；强制 stub 模型、临时库和关闭外部投递。
- API 启动修复：队列模式不再把独立 worker 所属的 `pending/running` 任务错误标记为重启失败。
- 反思输入修复：需要主管审批的动作在反思阶段使用 `pending`，并清除 `human_review + stop_reason=passed` 的矛盾组合。

## 实测结果

### 主系统完整联调

- 验收项：**19/19 通过**。
- 实际模型：`openai_compatible / deepseek-chat`，所有 7 个售后业务 Agent 均记录 `model_used=true`。
- 单条退款闭环：**33.27 秒，5,850 tokens**。这是一个样本，不是延迟或成本 SLA。
- HTTP 事实：订单、支付、物流、售后 4 类均写入，`is_mock=false` 表示走了真实 HTTP 适配器；数据内容仍来自本地合成 Sandbox。
- 故障场景：订单不存在、上游鉴权失败、无效 JSON 均在创建分析任务前安全停止；物流单源超时保留空事实和人工核验提示，没有伪造物流轨迹。
- 反思：实际执行一次复核，发现 3 项问题并输出 `human_review`，未自动修订，最终草稿由人工确认门禁接管。说明本样本验证的是“反思能拦截并升级”，不是“模型自动修好”。
- 审批：普通客服调用审批返回 403，审核员审批成功；未调用客户发送接口，也未执行真实退款。
- 指标：从 Sandbox 同步 `crash_rate`、`next_day_retention` 共 60 行到隔离库。

### 同机跨进程恢复

- 两个不同 Python PID：通过。
- 第一个进程退出后，待执行队列任务保留：通过。
- 第二个 API 进程启动未误伤队列任务：通过。
- 新 worker 领取遗留任务：通过。
- 人工中断 checkpoint 可见并从断点恢复：通过。
- 原始工作流未从头重复执行：通过。
- 范围仅为同机 SQLite；跨主机仍需 PostgreSQL/托管数据库演练。

## 结论与边界

本地优先级五项中，Sandbox 主系统接入、反思实跑、同机持久恢复和真实模型售后闭环已完成；真实 embedding/reranker 接入仍缺外部条件。本轮分项进度为 **4/5（80%）**。`production_ready` 仍为 false：本地合成接口、单条真实模型样本和同机 SQLite 恢复均不能替代企业真实端点、跨主机故障切换、独立 holdout 与真人客服试用。
