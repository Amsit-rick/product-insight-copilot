# 真实指标源发布门禁 P3-6（2026-11-09）

## 1. 审计结论

P3-4 已实现默认关闭的只读指标适配器和显式授权探针，但发布链路仍有三个缺口：

1. 探针没有 `generated_at`，发布报告无法判断证据是否过期；
2. 探针只调用一次，没有连续稳定性、延迟阈值或完整指标覆盖证明；
3. 预发布报告没有 `metric_source` 外部门禁，真实指标源即使缺失也不会进入机器发布证据。

此外，适配器虽然限制租户和指标白名单，但没有在 HTTP 边界拒绝请求日期窗口之外的数据。

## 2. 验收标准

- 默认模式继续禁止联网；
- 真实探针至少连续读取 3 次，并生成带时区时间戳；
- 证据只记录生产配置布尔值、版本存在性、行数、指标覆盖率和延迟，不泄露 URL、凭据、请求 ID 或指标值；
- 生产门禁要求 `APP_ENV=prod`、HTTPS、服务端鉴权、隔离租户、完整指标覆盖和延迟达标；
- 本地环境、单次调用、过期证据或不完整结果不能解除门禁；
- 适配器拒绝缺失必填字段、非法日期和请求窗口之外的记录。

## 3. 实现

- `HttpMetricSourceAdapter` 增加必填字段、数值类型、日期格式和日期窗口校验；
- `verify_metric_source.py` 增加 `--runs` 与 `--max-latency-ms`，默认连续 3 次；
- 探针增加脱敏 `configuration`、`summary` 和逐轮结构摘要；
- 预发布报告增加 `metric_source` 外部门禁及证据哈希；
- 发布清单和指标源契约统一使用固定的 `metric-source-result.json` 正式证据路径。

## 4. 安全边界

- 本轮不会访问真实网络；正向路径使用测试适配器验证。
- `production_ready` 仍由全部机器门禁和人工发布批准共同决定，指标源通过只能解除一个外部门禁。
- 本地默认探针必须保持 `external_network_used=false`、`production_ready=false`。
