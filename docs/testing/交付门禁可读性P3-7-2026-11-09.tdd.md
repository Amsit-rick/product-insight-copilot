# 交付门禁可读性 P3-7（2026-11-09）

## 1. 审计结论

正式发布报告已经能严格判定外部门禁，但交付摘要仍存在两个产品问题：

1. 六类门禁被压缩为长句，非研发人员无法快速判断哪一项未完成；
2. 固定的“交接后第一步”遗漏真实指标源、外部通知和独立 holdout 等新增门禁。

系统状态页已经显示指标源运行配置，但没有明确说明“配置可用不等于生产交付验收”，容易把运行健康误解为可以上线。

## 2. 实现

- 交付摘要增加“生产交付门禁”表格，逐项展示中文名称、当前状态和完成要求；
- 将 `missing` 等发布审批内部状态翻译为业务语言；
- 在本地证据表展示政策检索 Recall@5；
- 根据实际阻塞门禁动态生成交接下一步，不再维护容易过期的固定列表；
- 系统状态页增加醒目的边界提示，明确运行配置与生产验收不是一回事；
- 指标源区域分别说明“本地/演示指标不能作为生产告警依据”和“已配置仍需真实 SLA 证据”。

## 3. 验证标准

- 摘要中必须出现六类门禁的中文名称和状态；
- 真实指标源缺失时必须显示“待外部验证”及具体操作；
- 已验证门禁不得继续出现在“当前不能宣称”的阻塞列表；
- 页面必须明确出现“运行正常不等于已经通过生产交付验收”；
- 不新增一套脱离正式证据文件的伪实时生产状态。

## 4. 边界

系统页只负责解释当前运行配置；正式发布结论继续以预发布报告、交付检查、证据哈希和授权审批为准。
