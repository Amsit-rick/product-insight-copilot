# 镜像签名验签 P3-23（2026-11-10）

## 1. 目标与边界

本轮在 P3-21/P3-22 的 provenance 与 SBOM 闭环上增加镜像签名和验签，使发布镜像 digest、源提交 SHA 与独立签名证据形成可机器校验的绑定关系。

真实验证使用本机 Docker Desktop、官方 `docker:27-cli` Linux Runner 容器、共享 Docker socket 和回环 Registry。它证明平台无关脚本可以完成离线密钥签名和验签，但不属于企业 KMS、Sigstore keyless、透明日志、企业 Registry 或跨主机验证。

## 2. 完成的工程改造

### 2.1 签名验证器

- 新增 `backend/scripts/verify_image_signature.py`，解析 Cosign JSON claims；
- 强制镜像引用使用 `name@sha256:digest`，并校验 claims 中的 manifest digest；
- 校验 `release_sha` 注解与当前完整 Git SHA 一致；
- 只记录 16 位 SHA-256 公钥指纹，不把公钥正文或私钥写入证据；
- 固定输出企业能力边界，未验证项保持 `false`，不从本地签名推导生产就绪。

### 2.2 CI 与交付证据

- `scripts/ci-image-attestations.sh` 增加 `SIGN_IMAGE=true` 签名分支；
- Cosign v3.1.4 镜像按 digest 固定；
- 私钥写入一次性 Docker volume，使用随机密码，不落工作区；
- 使用不含 Fulcio、Rekor、OIDC 和 TSA 的显式离线 signing config；
- GitHub Actions 与 Gitee Go 模板均产出独立签名证据；
- release evidence bundle 强制附件由 4 类增加为 5 类，新增 `remote-ci-image-signature.json`。

## 3. 运行中发现并修复的问题

1. 最初选择的 GHCR digest 是 riscv64 单架构镜像，在 amd64 Runner 上无法执行。改为 Cosign v3.1.4 多架构 index digest。
2. Cosign v3.1.4 不再接受旧的 `--tlog-upload=false` 参数。改用显式离线 signing config，避免隐式访问透明日志服务。
3. Cosign 容器使用 UID `65532` 非 root 运行，新建 volume 默认不可写。使用固定 digest 的 Alpine 镜像只初始化 volume 所有权，随后签名仍由非 root Cosign 容器执行。
