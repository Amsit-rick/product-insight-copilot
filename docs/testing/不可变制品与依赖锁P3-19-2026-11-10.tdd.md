# 不可变制品与依赖锁 P3-19（2026-11-10）

## 1. 目标与边界

本轮完成 Python 依赖哈希锁、生产运行时依赖隔离、应用镜像版本绑定、无源码构建发布编排和单机 digest 运行验收。

验证只能证明本地 Windows 开发安装、Linux 容器构建和单机 Compose 运行形态可复现。镜像没有推送企业制品仓库，也没有跨主机部署、真实模型 holdout、真实 OMS/支付/物流/售后平台或人工发布批准，因此全部证据继续标记 `production_ready=false`。

## 2. 完成的工程改造

### 2.1 三套依赖锁

- `requirements-runtime.lock`：Linux 生产容器运行时锁，92 个包，不包含 pytest；
- `requirements-dev.lock`：Linux/macOS/CI 开发锁，97 个包；
- `requirements-dev-windows.lock`：Windows 开发锁，97 个包，排除 `uvloop`、包含 `colorama`；
- 所有依赖均为精确版本并包含 SHA-256，安装统一使用 `pip install --require-hashes`；
- `requirements.txt` 仅作为 Windows 兼容入口，引用 Windows 开发锁。

锁文件由 `pip-tools==7.6.2` 生成；Linux 锁编译环境固定为 `python:3.12-slim@sha256:f77ac9e44ae96ef2c90b8053ea08c31f8be030f824196b0ae4db6d462c84e51f`。

### 2.2 不可变镜像和发布编排

- Dockerfile 只安装 `requirements-runtime.lock`，生产镜像不携带 pytest；
- OCI `org.opencontainers.image.revision` 绑定完整 Git SHA；
- revision 标签位于依赖和应用层之后，提交号变化不会使依赖安装缓存失效；
- `docker-compose.release.yml` 使用 `!reset null` 删除五个应用服务的 `build`，只接受 `name@sha256:digest`；
- 新增依赖锁、发布 Compose 和镜像归档校验脚本；
- CI 与本地开发脚本均切换到对应平台的哈希锁。

### 2.3 运行中发现并修复的问题

1. Linux 开发锁在 Windows 安装时真实失败：`uvloop does not support Windows`。修复为 Windows 独立开发锁，没有通过跳过依赖掩盖问题。
2. MinIO `live` 健康检查先变绿，但 S3 端口对其他容器短暂拒绝连接，`minio-init` 单次调用会失败。修复为最多 20 次、间隔 2 秒的有界重试；空卷复验后初始化容器退出 0。
3. revision 标签原先位于依赖安装之前，每次提交都会重新安装 92 个包。已移动到镜像末端并增加顺序契约测试。
