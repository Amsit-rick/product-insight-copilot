# 政策检索质量门禁 P3-5（2026-11-09）

## 1. 问题

仓库已经有 `benchmark_policy_retrieval.py` 和一次 Recall@5 结果，但它未进入本地 CI、GitHub CI、预发布报告或最终机器门禁。新增政策切片后，即使检索质量下降，交付流程仍可能继续通过。

这不是“缺少一个数字”，而是质量证据没有形成闭环。

## 2. 验收标准

1. 本地 CI 与 GitHub CI 都必须运行零成本的政策 Recall@5 基准；
2. 发布报告必须读取本轮证据，并重新根据逐条用例计算 Recall@5 与 MRR；
3. 固定 `top_k=5`，至少 8 条用例，Recall@5 不低于 0.80；
4. 过期证据、汇总数字与逐条结果不一致、提高 top-k 放宽难度时必须失败关闭；
5. 该本地门禁只能作为生产发布的必要条件，不能替代真实模型 holdout、真实事实接口或人工批准。

## 3. 实现

- `backend/scripts/after_sales_release_report.py`
  - 新增 `policy_retrieval_benchmark` 本地证据状态；
  - 不信任 JSON 汇总字段，按 `cases` 重算 Recall@5 和 MRR；
  - 将校验结果和证据文件哈希绑定到发布证据摘要；
  - 新增 `--policy-benchmark-evidence`，允许 CI 使用本轮 `.tmp` 证据，避免依赖旧快照。
- `scripts/ci.ps1`
  - 在预发布报告前运行 Recall@5 门禁；
  - 证据写入 `backend/.tmp`，避免仅因刷新时间戳污染 Git 工作区。
- `.github/workflows/ci.yml`
  - 后端测试后增加独立 Recall@5 门禁。
- `RELEASE_CHECKLIST.md`
  - 增加人工发布时的对应命令。

## 4. 验证结果

- 发布报告专项：`27/27` 通过；
- 后端全量：收集 `1258` 条，`1257` 通过、`1` 跳过、`0` 失败；
- 当前政策基准：`8/8` 命中，`Recall@5=1.00`，`MRR=0.9375`；
- Python 编译：通过；
- PowerShell 语法及 UTF-8 BOM：通过；
- GitHub Actions YAML 解析：通过；
- Compose 主编排与演示编排静态解析：通过；
- 前端类型检查与生产构建：通过。

预发布报告联调识别为 `policy_status=verified_local`，同时继续返回 `production_ready=false`、`decision=not_ready_machine_gates`。

## 5. 边界

这套基准使用 stub embedding 和项目内合成问题，只能阻断本地政策召回回归。它不是独立人工标注 holdout，也不能证明真实 BGE-M3、Reranker 或生产语料上的召回率。

量化口径保持：本地工程改造 **99%**，生产交付准备度 **84%**，`production_ready=false`。
