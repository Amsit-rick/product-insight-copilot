# 目标节点发布准入门禁 P3-28（2026-11-10）

## 1. 目标

P3-20 至 P3-27 已分别形成镜像发布回滚、provenance/SBOM、签名、Runner 准入和 TLS/Auth Registry 证据，但这些证据来自不同提交、不同镜像摘要和不同验证范围。P3-28 的目标是阻止操作者把多批次证据人工拼接后误判为同一候选版本已经具备发布条件。

本阶段只建立机器准入判定，不执行最终发布，也不替代授权人员审批。

## 2. 工程改造

新增 `backend/scripts/verify_target_release_admission.py`，同时读取并校验：

1. Runner 准入证据；
2. provenance / SBOM 证据；
3. 镜像签名证据；
4. 供应链 bundle；
5. TLS / Basic Auth Registry 控制证据；
6. Registry 发布、digest 拉取与应用回滚证据；
7. 目标环境实时探针证据。

门禁验证以下内容：

- 七类证据 schema 和最大文件大小；
- bundle 中 Runner、attestation、signature 的 SHA-256；
- 完整 40 位 Git SHA 是否全部绑定同一候选版本；
- bundle、attestation、signature 与 rollout 是否绑定同一镜像 digest；
- provenance、SBOM、签名及 `release_sha` 注解；
- TLS、未信任 CA 拒绝、Basic Auth 和错误凭据拒绝；
- Registry 发布、按 digest 拉取、部署和队列探针；
- 目标运行形态、企业 Registry 与跨主机状态；
- 证据生成时间是否在允许窗口内；
- 任一输入证据不得自行声明 `production_ready=true`。

输出包含七份输入的 SHA-256 和 `admission_bundle_id`，用于固定本次判定批次。即使所有机器检查通过，输出也只能是 `machine_ready_awaiting_human_approval`；工具始终保持 `release_authorized=false` 和 `production_ready=false`。

活动 Gitee 远程契约测试已纳入 P3-28 单元测试，不要求托管 Runner 具备 Docker。
