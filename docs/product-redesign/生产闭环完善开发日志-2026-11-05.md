# 生产闭环完善开发日志（2026-11-05）

## 本轮目标

围绕以下成熟闭环标准继续改造：

```text
状态可续 + 判定独立 + 全程可回放 + 授权分粒度 + 改动有节奏
```

## 已完成

### 1. 生产状态续接门禁

- `APP_ENV=prod` 强制 `TASK_EXECUTION_BACKEND=queue`；
- `APP_ENV=prod` 强制 `WORKER_EMBEDDED=false`；
- `APP_ENV=prod` 强制 `CHECKPOINTER_BACKEND=postgres`；
- 门禁在建表、播种之前执行，错误配置直接拒绝启动；
- 本地、开发和测试环境保持原有零依赖体验。

### 2. 任务级确定性历史播放

- 新增 `task_replay_snapshots` 不可变快照表；
- `ToolCall` 新增完整脱敏 `result` 与 `result_digest`；
- 回放包包含任务输入、版本、事件、Agent 输出、工具结果、引用、审批、报告和审计；
- 移除思维链/推理字段，手机号、地址、支付凭证、密钥和令牌统一脱敏；
- 同一任务状态重复生成快照按 `(task_id, digest)` 幂等复用；
- 新增 SHA-256 完整性校验；
- 明确区分 `playback` 与重新执行 `rerun/retry`；
- 旧任务缺失完整工具结果时标记 `playback_fidelity=partial`。

接口：

```text
POST /api/v1/tasks/{id}/replay-snapshots
GET  /api/v1/tasks/{id}/replay
POST /api/v1/tasks/{id}/replay/verify
```

### 3. 回放权限

- 新增动作权限 `task:replay`；
- 仅管理员和审核角色可创建、读取和校验回放包；
- 普通 `task:read` 不再隐式获得完整回放数据访问权。

### 4. 数据库与文档

- 新增 `009_task_replay.sql`；
- 同步 `001_init.sql`，保证新库与增量升级一致；
- 存量 SQLite 演示库启动时幂等补齐 `tool_calls.result/result_digest`；
- 更新发布清单和 README，生产不再允许 SQLite Checkpointer。

### 5. 统一 RBAC + ABAC 授权入口

- 新增统一授权输入输出，所有结论固定为 `allow / deny / require_approval`；
- 统一执行租户边界、RBAC 动作基线、资源级 ABAC，并返回原因、命中策略和有效范围；
- 任务回放和指标读取已接入统一授权，`require_approval` 不再被当成普通允许；
- 新增管理员授权预演接口 `POST /api/v1/access-policies/authorize-simulate`；
- 任务回放授权决定写入独立审计记录。

### 6. 策略条件失败关闭

- 抽取共享的策略条件校验与时间判定模块；
- 通用资源和指标资源统一执行有效期、工作时间与策略时区；
- `departments` 明确匹配访问者所属部门；
- 金额、风险等级、数据分类、工具名和密级条件均有实际判定语义；
- 管理端拒绝非法时间、无效日期、空条件集合和反向金额区间；
- 历史脏策略在运行时失败关闭，不再静默当作无限制。

### 7. 访问策略管理界面

- 原“指标密级策略”升级为“访问策略”；
- 支持任务回放、工单、知识库、文档、工具、指标和数据集等资源；
- 支持允许、拒绝、需人工审批三种处理方式；
- 授权预演直接展示“谁、对什么资源、做什么、最终结论、为什么、是否命中策略”；
- 保留附加业务条件，但默认页面不再用策略表字段堆砌技术概念。

### 8. 反思机制细粒度灰度

- 新增服务端稳定哈希分桶，同一 `task_id` 始终落在同一组；
- 支持按租户、风险等级、问题类型和 0~100% 比例限定反思范围；
- 售后回复与诊断报告使用同一判定服务，调用方传入的开关不能绕过门禁；
- 暂停和回滚状态优先于百分比，回滚后强制 0% 覆盖；
- 判定结果写入任务 filters、执行事件和 AgentRun 元数据，但不保存 Prompt 或思维链；
- `/health` 只公开灰度范围、比例、样本门槛等非敏感配置。

### 9. 发布节奏、停止扩大与回滚门禁

- 新增租户级 `reflection_release_states` 持久化状态表；
- 独立代码判定样本量、错误率、安全违规、受保护字段违规、有界终止率、P95 延迟、Token 和人工审核率；
- 样本不足时只返回 `hold`，不制造“效果更好”的结论；
- 安全硬指标失败时可自动回滚到 0%，并记录审计；
- 延迟或 Token 严重恶化时返回 `pause`，阻止继续扩大；
- 达标时只建议按 `10 → 25 → 50 → 100` 阶梯扩大，必须管理员确认，不允许系统静默放量；
- 新增接口：
  - `GET /api/v1/experiments/reflection-release`
  - `POST /api/v1/experiments/reflection-release/decision`

### 10. 运维界面

- “系统状态”新增“反思灰度与发布门禁”区域；
- 只展示当前覆盖、作用范围、样本量、系统建议、原因和操作按钮；
- 管理员可重新评估、暂停、恢复、批准阶梯扩大或回滚到 0%；
- 总开关关闭时明确提示“比例保留但实际不执行”，避免把配置值误认为已生效。

### 11. 自动回滚运行告警闭环（2026-11-06）

- 新增 `operational_alerts` 持久表，运行告警与不可变审计日志分开管理；
- 同一租户、同一告警指纹重复发生时合并计数，避免重复刷屏；
- 已解决或已确认的告警再次发生时重新打开，防止旧状态掩盖新事故；
- 反思灰度自动回滚会同时生成严重告警和审计记录，原因、来源与发生次数均可追踪；
- 管理员可查看、确认已看到、标记已解决；普通角色不能读取或操作技术告警；
- “系统状态”新增运行告警区，优先显示严重未解决数量、发生时间和处理按钮；
- 修复系统状态页“最近缓存窗口”标签显示原始模板文本的问题。

接口：

```text
GET  /api/v1/operational-alerts
POST /api/v1/operational-alerts/{id}/acknowledge
POST /api/v1/operational-alerts/{id}/resolve
```

### 12. Webhook 外部通知 outbox（2026-11-06）

- 默认关闭，不配置地址时不会发出真实网络请求；
- 严重告警与 Webhook 投递记录在同一数据库事务内写入，避免告警已提交但通知任务丢失；
- 后台投递线程独立处理网络请求，不占用业务事务；
- 同一告警同一次发生只入队一次，复发会生成新的投递记录；
- 多 worker 通过条件更新原子领取，避免重复投递；
- 支持 HMAC-SHA256 签名、超时、指数退避、租约过期回收和最大尝试次数；
- 408/425/429/5xx 进入重试，普通 4xx 直接进入死信；
- 管理员可查看 Webhook 死信并手工重放，操作写入审计；
- 投递列表与汇总均按当前租户隔离，不能看到其它租户的死信数量；
- `/health` 和系统状态页只展示开关、签名状态与队列计数，不回显 URL 或密钥；
- 生产启动时启用 Webhook 必须使用完整 HTTPS 地址，禁止 URL 内嵌用户名或口令。

新增接口：

```text
GET  /api/v1/operational-alerts/deliveries?status=dead
POST /api/v1/operational-alerts/deliveries/{id}/replay
```
