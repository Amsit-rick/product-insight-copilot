# 售后工作台客服无指导测试任务包

本任务包用于组织真实客服或主管进行第一次无指导试用。它把测试数据准备、主持人口令和记录口径分开，避免把自动化回归结果冒充用户体验结果。

## 1. 准备环境

在项目根目录执行（Windows CMD）：

```cmd
cd /d D:\path\to\product-insight-copilot
\.venv\Scripts\python.exe -m app.db.seed
\.venv\Scripts\python.exe backend\scripts\prepare_usability_test.py --analyze
# 如需给记录工具读取准备状态：
\.venv\Scripts\python.exe backend\scripts\prepare_usability_test.py --json-out docs\testing\artifacts\usability-prep.json
# 如果按演示脚本使用 8010 端口：
\.venv\Scripts\python.exe backend\scripts\prepare_usability_test.py --base-url http://127.0.0.1:8010
```

脚本默认使用 stub/mock 适配器，不调用真实模型。若当前环境配置了真实模型，脚本会沿用 `demo_tickets.py` 的费用保护，需要显式确认后才会执行。

启动服务后，参与者访问准备脚本输出的 `test_url`。零依赖开发默认是 `http://127.0.0.1:8000/#/login`；按演示脚本启动隔离服务时通常是 `http://127.0.0.1:8010/#/login`。

演示账号：

| 角色 | 账号 | 密码 | 测试范围 |
|---|---|---|---|
| 客服 | `ops` | `ops123` | 任务 A-D |
| 主管/质检 | `reviewer` | `reviewer123` | 任务 A、B、E |

## 2. 主持人任务卡

主持人只读下列口令，不告诉参与者要点击哪个菜单，也不解释技术术语。

| 任务 | 演示工单 | 口令 | 通过标准 |
|---|---|---|---|
| A 找到下一步 | `TK-260924-0186` | 找到你认为应该优先处理的工单，并说出客户问题、下一步和是否超时。 | 能打开详情并用业务语言复述问题、下一步、时限。 |
| B 判断审批 | `TK-260924-0184` | 这张工单涉及退货退款，请判断现在能否直接发给客户，下一步怎么做？ | 能识别需主管审批，知道未审批不能承诺退款已执行。 |
| C 准备回复 | `TK-260924-0181` | 使用一个常用回复作为起点，改成你愿意发给客户的话，但先不要发送。 | 能使用模板并修改草稿，不把模板操作当成发送。 |
| D 内部协作 | `TK-260924-0186` | 留一句客户看不到的备注并 @ 售后主管，请他关注这张工单。 | 能完成内部备注，知道客户不可见；主管能在待我关注中找到。 |
| E 维护话术 | 无固定工单 | 新增一条物流问题常用回复，并把它停用。 | 主管能完成新增和停用；客服看不到维护入口。 |

## 3. 记录和判定

逐项记录独立完成、耗时、误操作、卡住位置和用户原话，使用：

`docs/product-redesign/客服可用性测试记录模板.md`

需要结构化校验时，使用 `backend\\scripts\\validate_usability_test_record.py` 生成 JSON 模板并在测试后输出脱敏汇总；汇总不会替业务方判断是否达标。正式记录还必须确认参与者均为非研发人员，并完整填写测试日期、主持人、18 项任务观察值和结论。

不要填写模拟结果。建议至少邀请 3 名一线客服和 2 名主管/质检；正式交付前仍以真实业务方确定的样本量为准。

阻断条件：

- 用户把“待主管审批”理解为退款已经执行；
- 用户把内部备注发送给客户；
- 用户找不到下一步或无法判断是否超时；
- 客服账号看到主管模板维护或质检管理入口。

这些问题应先按 P0/P1 修复并回测，再扩大试点。任务包本身不产生“无指导完成率”或“处理时长改善率”。

预发布报告只会在至少 5 名非研发参与者、全部任务完整观察、测试元数据与结论齐全、未解决 P0/P1 为 0，且历史 P0/P1 已有整改回测时，解除 `usability_test` 单项门禁。其他生产门禁不会因此自动通过。
