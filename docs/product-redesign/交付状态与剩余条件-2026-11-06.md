## 本轮发现并修复

1. Compose 原先只通过 ORM `create_all` 建表，没有执行版本化迁移；新增一次性 `migrate` 服务和启动门禁。
2. `001_init.sql` 把 `recommendations` 的唯一约束错误放在 `order_facts`，导致全新 PostgreSQL 迁移失败；已修复并增加约束归属测试。
3. 负载脚本使用非法 `channel=loadtest`，24 次请求全部 422；改为合法 `api` 并标记 `data_origin=test`。
4. 多进程专项环境关闭了提交限流，无法证明 Redis 全局计数；隔离负载环境改为每分钟 5 次。
5. 崩溃脚本只能杀宿主机 Python，无法验证 Docker Worker；新增按 `claimed_by` 精确删除容器的 Docker 模式。
6. 恢复脚本把迁移数量写死为 6；改为按当前 `migrations/*.sql` 动态计算。
7. README、发布清单和部署说明中的旧测试数量、表数、灰度及死信描述已校准。
8. 工具返回的 `datetime/date/Decimal` 原先会导致 `tool_calls.result` 审计写库失败；新增结构化 JSON 规范化与回归测试，保留金额精度和嵌套结构。
9. 预发布报告原先把本机 Docker 演练与目标生产环境混为一个外部门禁；现已拆分为 `local_production_shape_verified=true` 与 `cross_host_or_target_environment_verified=false`。
10. 默认 Compose 会拉取未启用的 MinIO 初始化镜像，导致干净重建失败；现将 MinIO/Qdrant 改为可选 profile，默认使用本地对象存储与 pgvector。
11. 浏览器 E2E 仍使用旧的“密级策略 / 权限预演”文案和硬编码拒绝结论，导致实际“访问策略 / 授权预演”功能被误报失败；测试已按当前产品契约校准，并保留对结论、原因和命中策略的真实结构断言。
12. 发布文档要求在容器中运行 preflight，但最终镜像原先没有包含脚本和事实探针计划；现已将两者随镜像发布，并通过 `.dockerignore` 精确白名单只放行脱敏 JSON 模板。
13. 严格 preflight 原先没有独立检查真实 Embedding、Reranker 和外部告警，且把本地对象存储直接判为 PASS；现已补齐 24 项门禁，stub/启发式/站内告警/单机落盘在严格模式下都会阻断生产结论。
14. 原 `verify_stability.py --dry-run` 只能显示模型路由，无法分别证明 LLM、Embedding 和 Reranker 协议可用；新增最小 AI 接入探针，真实模式只发送三次小请求，并且证据不保存回答、向量、候选原文、端点或密钥，Embedding 维度不一致会直接失败。
15. 事实接口验收脚本原先未进入最终镜像且每次必须手工传计划路径；现已随镜像发布并自动兼容源码/容器布局，宿主机与容器内计划校验均通过。
16. 真实 HTTP 事实端点原先允许 URL 内嵌用户名/口令，生产环境也未强制 HTTPS；现已阻断内嵌凭据、URL 片段和生产 HTTP。404 错误不再把原始订单号复制到持久化错误文本。
17. Webhook 原先只有单元 MockTransport 测试，没有随镜像交付的独立验收入口，且生产启动门禁没有强制 HMAC；现新增本地回环闭环和显式真实最小投递模式，生产启用时同时强制 HTTPS、无 URL 凭据/片段和 HMAC 密钥。
18. DEBUG/INFO 日志原先会由 `httpx/httpcore` 输出完整外部请求 URL，可能暴露模型、事实接口或 Webhook 的内部路由；统一日志初始化现将两个第三方客户端降到 WARNING，只保留不含端点的应用级失败摘要。
19. 对象存储原先缺少 `boto3` 运行依赖，显式 MinIO 初始化失败还会静默回退本地目录；现已补齐依赖并改为失败即失败，避免多副本数据分裂。
20. 本地存储 key 原先缺少路径穿越防护，生产启动与 readiness 也不检查共享存储；现已加入 POSIX key 校验、桶连通检查、`/health/ready` 存储项和生产共享存储门禁。
21. 原固定 MinIO/MC 镜像坐标无法拉取，健康探针也假设服务镜像内存在已配置的 `mc`；现改为明确仅供本地验收的固定兼容镜像、HTTP 健康端点和同镜像建桶客户端，并完成实际拉取与启动验证。
22. Compose 原先写死 `MINIO_ENDPOINT=minio:9000`、`MINIO_SECURE=false`，且应用凭据绑定管理员账号；现允许覆盖企业 HTTPS 端点和独立应用账号，生产门禁拒绝明文对象存储。
23. 新增默认不联网的 `verify_object_storage.py`；只有显式授权才执行 put/get/delete。探针使用 `shared_storage_ready` 表示单项通过，不能把本地 MinIO 误报为系统生产就绪。
24. 新增默认不联网的 `verify_target_environment.py`；只有显式授权才访问目标节点，且单节点、测试环境或未确认不同主机时均不能解除生产基础设施门禁。
25. 客服记录原先只校验格式，容易把“模板完整”误读为“真人测试完成”；现加入非研发身份确认、18 项完整观察、测试元数据、未解决 P0/P1 和整改回测门禁。
26. 真实事实接口和 Webhook 探针原先即使通过也不会进入预发布报告，外部门禁没有正向路径；现已接入固定证据文件并要求 24 小时新鲜度、带时区时间戳和完整协议检查。
27. 交付检查与摘要原先从本机 Docker 证据读取跨主机状态；现改为读取独立目标环境证据，并增加明确的“目标环境多节点”发布检查。
28. 真实模型 holdout 原先只有运行手册，没有可被预发布报告识别的正向证据契约；现增加固定证据、四项显式业务阈值、至少 3 轮、真实模型调用/完整价格/安全指标检查和 168 小时新鲜度门禁，缺失或不合格时失败关闭。
29. `production_ready` 原先永久写死为 false，虽然不会误报，但所有真实证据完成后仍没有合法正向路径；现新增绑定提交和证据摘要的结构化人工批准，并在交付检查中二次核对 v4 契约、机器门禁和批准匹配状态。
