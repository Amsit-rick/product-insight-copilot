# 售后工单系统预发布验收清单

这份清单区分“本地工程证据”和“必须由业务/平台方提供的外部证据”。本地 stub、mock、自动化回归和演示数据不能替代真实平台验收。

## 一键生成本地报告

在 Windows CMD 的项目根目录执行：

```cmd
.venv\Scripts\python.exe backend\scripts\after_sales_release_report.py --json-out docs\testing\artifacts\after-sales-release-readiness.json
```

报告会检查：

- 常规和严格 preflight 状态；
- Git 提交 SHA、分支、上游同步状态以及暂存、未暂存和未跟踪改动；
- 事实接口验收计划是否完整；
- 演示租户的关键测试工单是否存在；
- 真实平台、消息渠道、生产基础设施、真实模型和客服测试等外部阻塞项。
- 固定证据文件中的真实事实接口、真实 Webhook 和目标多节点结果是否为 24 小时内的有效活体证据；
- 真实模型 holdout 是否为 168 小时内、至少 3 轮、每轮至少 200 条且所有安全与业务阈值均通过的有效证据。
- 最终发布批准是否由授权角色完成，并与当前提交和本次机器证据 SHA-256 完全匹配。

报告中的 `production_ready=false` 是当前预期结果，不能通过增加 mock 数据绕过。

## 候选版本一键验收

在 Windows CMD 的项目根目录执行：

```cmd
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\ci.ps1 -WithE2E
```

执行完成后重点查看：

- `docs\testing\artifacts\after-sales-release-readiness.json`：完整机器报告；
- `docs\testing\artifacts\after-sales-delivery-check.json`：候选版本门禁；
- `docs\product-redesign\售后候选版本交付摘要.md`：业务/运维交接摘要。

`local_demo_ready=true` 只表示本地 mock 演示链路可运行。`candidate_ready=true` 必须同时满足严格 preflight、真实事实适配器、干净且与上游同步的 Git 版本、全部外部门禁和 `production_ready=true`；当前预期仍是 `candidate_ready=false`、`production_ready=false`。

## 外部验收门

| 项目 | 责任方 | 必须提供的证据 |
|---|---|---|
| 事实平台 | OMS/支付/物流/售后平台方 | 匿名订单、只读授权、四个端点、404/超时故障场景；至少 3 轮真实探针写入 `fact-integration-result.json` |
| 消息渠道 | 业务/平台方 | 测试账号、发送回执、撤回/失败策略和回滚开关；真实 HTTPS 投递写入 `webhook-integration-result.json` |
| 生产基础设施 | 运维 | 至少两个生产节点的 PostgreSQL、Redis、队列 worker、共享 checkpointer、共享存储实时检查，写入 `target-environment-result.json` |
| 真实模型 | 模型/业务方 | 价格配置、真实密钥、至少 200 条独立人工标注脱敏 holdout；真实模型与真实事实接口至少 3 轮，业务负责人明确通过率、一致性、证据支持率和 P95 阈值，写入 `real-model-holdout-result.json` |
| 可用性 | 业务负责人 | 5 名非研发客服/主管记录、P0/P1 修复和回测结果 |
| 最终发布决定 | 授权业务/技术/运维发布角色 | `release-decision.json`：approve/reject、角色、审批引用、当前提交、证据 SHA-256、风险接受和回滚确认；最长 24 小时，提交或证据变化后重批 |

任何一项外部证据缺失，都只能称为“本地演示可运行”，不能称为发布候选可交付或生产已验收。
事实接口、Webhook 和目标环境证据必须包含带时区的 `generated_at`，且报告生成时不超过 24 小时；
真实模型 holdout 证据最长接受 168 小时，且不得包含逐条 case 的输入、订单标识或判断详情；
机器门禁全部通过仍不等于已批准发布，固定批准文件缺失、拒绝、过期或与提交/证据不匹配时，
`production_ready` 必须保持 `false`；
计划校验、本地回环、单 runner 或手工自述不属于真实外部证据。

## strict preflight 11 项失败分类（2026-11-08）

`python backend/scripts/preflight_check.py --strict` 当前 **25 项：10 PASS / 4 WARN / 11 FAIL**。
11 项失败均为生产配置或外部依赖，不是本地代码回归；常规档为 **10 PASS / 15 WARN / 0 FAIL**。

| 检查项 | 类别 | 当前原因 | 关闭条件 |
|---|---|---|---|
| Embedding | 外部服务 | `EMBEDDING_PROVIDER=stub`，使用确定性哈希向量 | 接入 BGE-M3 等真实 Embedding 端点与密钥 |
| Reranker | 外部服务 | `RERANKER_ENDPOINT` 未配置 | 提供可访问的 BGE-Reranker 服务 |
| 事实适配器 | 外部服务 | `TICKET_USE_MOCK_ADAPTERS=true` | 关闭 mock，配置订单/支付/物流/售后 4 个只读端点与鉴权 |
| 指标事实源 | 外部服务 | `METRIC_SOURCE_HTTP_ENABLED=false` | 启用只读指标源并配置 URL、指标白名单与鉴权 |
| 外部告警 | 外部服务 | `ALERT_WEBHOOK_ENABLED=false` | 配置 HTTPS 接收端与 HMAC 共享密钥，并完成送达演练 |
| JWT 密钥 | 生产配置 | 仍是示例占位值 | 生成 32 字节以上随机密钥 |
| CORS | 生产配置 | 仅允许 localhost 开发来源 | 改为生产前端域名白名单 |
| 登录限流 | 配置 + Redis | 10 次/分钟，但 `CACHE_BACKEND=auto` 未实际使用 Redis | 配置可用 Redis，多副本共享计数 |
| 演示数据播种 | 生产配置 | `AUTO_SEED=true` | 生产设置 `AUTO_SEED=false` |
| 对象存储 | 配置 + 基础设施 | `STORAGE_BACKEND=local`（单机落盘） | 接入 HTTPS MinIO/S3 与独立最小权限账号 |
| 任务执行 | 配置 + 基础设施 | `TASK_EXECUTION_BACKEND=threadpool` | 切 `queue`、`WORKER_EMBEDDED=false`，并配置共享 checkpointer |

前 5 项必须由外部服务/凭据提供；后 6 项可通过生产环境变量收口，但依赖 Redis、对象存储、独立 worker 等基础设施就绪。
在这些项关闭前，`local_demo_ready=true` 只代表本地演示可运行，`candidate_ready` / `production_ready` 必须保持 `false`。
